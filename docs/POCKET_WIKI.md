# Pocket Wiki

Pocket Wiki is a bundled client add-on (`community.pocket-wiki`, client API v2).
It browses crafting recipes, explicit equipment upgrade links, material sources
and reverse uses inside the game. It complements the native wiki already present
in client 2.0.112, which supplies equipment pages, upgrade details and drops.

The game is authoritative. Update it even when Pocket Wiki needs a compatibility
fix. Client updates can require adapter support and a fresh review; content updates
require a reviewed reference-data refresh. An older wiki snapshot must never be
used to overwrite newer game content or hold back a game update.

## Install and open

1. Start Studio and open **Add-on settings**. Select **Normal game client**.
2. Close that game client. The game server can stay running.
3. Open **Discover add-ons → Pocket Wiki → Review install**. Read its reference
   coverage and file changes, then apply the plan. Changed pack files have backups.
4. Launch the game using your usual shortcut and connect normally.
5. Enter a character, then click **Pocket Wiki** near the top-left of the game
   screen or press **Ctrl+U** with chat closed. Studio does not need to stay open.

To change how it opens, go to **Studio → Installed add-ons → Pocket Wiki → Details**.
**Shortcut** offers Ctrl+U, F12 or no shortcut; **Show button** controls the launcher.
Close the client, review/apply the settings change, then launch it again. Existing
game-key registrations and focused chat/whisper input take priority. If the
shortcut is already used by the game, use the button or choose another shortcut.

If neither route appears, check that Pocket Wiki is **installed and enabled**, not
merely available in Discover or downloaded. Installing Boss Atlas does not install
Pocket Wiki. Apply Pocket Wiki's own installation plan and launch that selected
client again.

No extra playable client is required. Optional development targets remain under
**Advanced testing tools**. After a game update replaces the packs, use **Review
reapply** to review installed add-ons on the new game baseline. Removing the last
add-on restores that current baseline. Unknown executable integrations can require
adapter support; updating and playing the game remain independent of Studio.

## Browse

Search item names/IDs, crafts or NPCs. Client-localised item names and exported
catalog names are both searchable. Tabs restrict the results. Select a recipe to
inspect clickable ingredients, outputs, Yang, base chance and known NPC access.
Item pages show linked upgrade steps, configured sources and reverse uses.

**Back/Next**, **Bookmark**, **History** and a compact **Pin** card keep useful
answers close. The attempt buttons calculate ingredient/cost totals for crafting
attempts; output quantities remain per successful attempt. A successful outcome,
scroll protection or an effective runtime probability is never promised.

**Native wiki** opens the selected item's existing native page when available.
**Resize +/-** switches compact/expanded layouts, clamped to the screen. **Reset**
restores an accessible layout. **Info** reports snapshot version and coverage.

Bookmarks, recent pages and window preferences are stored in a bounded JSON file
under `%LOCALAPPDATA%/Metin2Studio/addon-preferences/<world-id>/`. A previous complete
generation is retained for recovery. No pack rewrite is needed to bookmark a page.
Disabling/removing the add-on leaves those personal preferences available for a
later reinstall. Runtime preferences are separate from reviewed manifest settings.

## Reference data and refresh

The index is generated locally by Studio during an explicit install, update or
**Review reference-data refresh**. GET/startup does not query the database or
regenerate the reference index. The installed wiki works offline with Studio shut.

Generation reads captured saved files outside staged change sets and draft source
views. Native crafting reads a consistent current database snapshot when available,
without applying saved Studio overrides. Otherwise it uses labelled seeds.

Every index has a schema, content snapshot hash, generation time, server version,
counts, per-record provenance and coverage notes. Input bytes and live recipe rows
are rechecked during review/apply; changed generated bytes invalidate the plan.
The first reference export for the inspected world contained 246 recipes and
2,662 usable upgrade links. Counts depend on each installation.

Coverage is deliberately explicit:

- Cube and drop references describe saved configuration. Docker build-time
  transformations, engine modifiers and additional Herbalist drop sources can
  change the effective tables. A matching source hash does not prove deployment.
- Upgrade and shop references use the installed SQL seed.
- Native crafting is labelled database snapshot or database seed. Discovering an
  NPC menu does not prove a particular character meets its entry requirements.
- Dynamic quest rewards, dynamic encounters and unrecognised rules can be missing.
- Shared reward pools remain distinct from physical chests. Zero/unusable routes
  are excluded. Upgrade traversal follows explicit links and guards cycles.

Generate a fresh snapshot after updating or applying game content. This is a
reviewed client-data operation, separate from server Apply and code-package updates.

## Implementation and verification

Original add-on code lives in `src/metin2_studio/addons/catalog/community.pocket-wiki/`. The
structured exporter is `src/metin2_studio/addons/knowledge.py`; API v2 services are
`src/metin2_studio/addons/runtime/m2hub_client.py`. Game integration wraps `GameWindow.Open` after
its original call, `Close` before teardown and `OnKeyDown` with input guards.
Atlas API-v1 callbacks keep their existing behaviour.

Run `python -m unittest discover -s tests -t . -p test_pocket_wiki.py -v` for correctness,
lifecycle, preferences, playable-copy guards and reviewed-refresh tests. Full
regression tests and `tools/check_project.py` also apply.

`python -B tools/check_pocket_native.py --run` creates its own owned playable copy,
installs the bundled add-ons and temporarily substitutes an original startup
harness. It checks native widgets/navigation and captures a rendered screenshot
without logging in. The copied startup pack is restored even if the harness fails.
Private reports/assets stay outside source releases. Synthetic lifecycle/native
rendering evidence is distinct from interactive gameplay on a connected server.
