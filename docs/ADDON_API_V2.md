# Client API v2

API v2 adds independent game windows and world-local reference data. Managers now
accept explicit versions 1 and 2; omission still means v1. Unknown versions are
rejected. API-v1 packages retain their atlas events and context behaviour.

An API-v2 manifest uses `api_version: 2`. Code remains Python-2.7 compatible for
client 2.0.112. Declare descriptive capabilities such as `ui.window`,
`knowledge.read` and `preferences.local`. Capabilities describe composition needs;
trusted Python is not a privilege sandbox.

| Context member | Contract |
| --- | --- |
| Existing v1 members | `id`, `settings`, `on`, `world`, `log` remain available |
| `on('game.open', callback)` | Called with game window after original Open |
| `on('game.close', callback)` | Called with game window before original Close |
| `module('m2hub_addons.name')` | Load an installed namespaced helper with the host's embedded pack loader |
| `register_window(name, factory, shortcut='NONE')` | Register one lazy factory receiving the game window; returns handle with `toggle()` |
| `addons()` | Read installed id/name/version/status records and available window/atlas actions; disabled add-ons remain listed |
| `open_addon(id, action=None)` | Open a registered action on an enabled, loaded add-on; raises an existing window without closing it; returns availability |
| `reference()` | Schema-1 locally generated structured knowledge index; treat as read only |
| `load_state()` | Load this add-on's world-local preferences or an empty object |
| `save_state(object)` | Save at most 32 KiB of JSON with a previous-generation recovery copy; returns success |
| `open_native_item(game, item_id)` | Best-effort native-wiki deep link; returns availability |

Names must be unique within an add-on. Factories return owned windows providing
`IsShow()`, `Open()`, `Close()` and `Destroy()`. Destroy releases references and
widgets. The host disposes windows on game Close and registration failure. A
window failure disables that handle until the next game session and logs a trace.
Lifecycle callback failures retain the v1 policy: disable the failing callback.

Shortcuts are `CTRL_U`, `F12` or `NONE`. Duplicate add-on registrations are refused.
Registered game bindings and focused chat/whisper/IME input take priority. Retain
an on-screen route because shortcuts can be unavailable in another client profile.
The host owns all shared lifecycle/input patches; add-ons register handlers.

Runtime preferences are mutable personal UI data. Manifest settings continue to
use reviewed pack transactions. Keep preferences bounded and tolerate stale IDs.
Preferences are scoped by world and add-on, independently of package version.

Reference code/data are separate: distributed packages contain original code;
world-specific generated bytes are included only in reviewed local composition.
`refresh-data` regenerates an enabled `knowledge.read` package's index without
changing its code version or settings. Source changes invalidate reviewed bytes.
The current index describes installed configuration/seeds/current native recipe
snapshots according to its provenance; it does not certify effective engine rules.

Game-profile compatibility is independent of API compatibility. Actual gameplay,
localised fonts, resolutions and frame costs require their own evidence. The
normal-client adapter accepts recorded executable integrations with reviewed pack
writes and backups. Optional playable copies remain available for development. See [Pocket Wiki](POCKET_WIKI.md) for usage/coverage.

## Add-on Menu

`community.addon-menu` is a normal API-v2 package, not a forced runtime widget. It
registers its own menu window and game-lifecycle launcher button. Installed names
and enabled states come from generated `INSTALLED_ADDONS`; active modules remain
in `ADDONS`. The host exposes only registered window actions and native atlas
opening, never loads disabled modules on demand or writes installation settings.
Failed window factories are isolated using the existing session failure guard.
Multiple registered windows expose separate actions. The menu lists itself first.
