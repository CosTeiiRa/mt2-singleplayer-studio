# Dashboard captures

The seven JPEGs show the Studio dashboard used for the beta-1.0.0 documentation, connected to game package 2.2.106. They were captured on 17 October 2026 from the browser UI, without changing game configurations or deploying anything. The additional PNG was supplied by the user on 18 October 2026; it shows update protection on game package 2.2.108. That illustration does not extend the release's tested compatibility claim.

- `economy.jpg`: aggregate live-world metrics with GM accounts excluded; the figures are one world's observed values, not promised outcomes or a complete inflation measure.
- `drop-editor.jpg`: installed Metin of Sorrow drop group, with the reward list scrolled to individual items.
- `item-search.jpg`: item picker filtered to bonus items, without selecting a replacement.
- `item-usage.jpg`: read-only references for Skill Book.
- `quest-builder.jpg`: a new, unsaved hunt template with its guided fields and generated source.
- `native-crafting.jpg`: existing Baek-Go potion recipe, opened without editing it.
- `rollback-review.jpg`: preview of an existing configuration rollback, closed without confirming it.
- `update-protection.png`: historical user-provided capture showing the former keep-custom update review. Since alpha-1.8.1 game values take priority, so this capture is no longer used as current update-workflow documentation. Adding the image did not perform a merge or Apply.

The quest and crafting editors use full-page captures so their fields and review controls remain visible. The drop editor, picker, reference explorer, economy overview and rollback dialog use viewport captures. Images have not been retouched. They show game content and aggregate statistics, without credentials, personal server paths or character/account identities.

To refresh them, use a dedicated browser tab, open the same read-only views, wait for data and icons to load, and capture the browser UI as JPEG. Preserve the original format of supplied captures. Never save or Apply a game change merely to stage a documentation image. Check every replacement visually and keep the relative image links in the root README working.
